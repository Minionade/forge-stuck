# Forge 1.20.1 Compatibility Inventory

Last scanned: 2026-10-18

This inventory tracks bytecode references in the supplied Minecraft 1.20.1 Forge mod jars. The detailed, deduplicated call and field reference list is in [forge-1.20.1-call-inventory.tsv](forge-1.20.1-call-inventory.tsv). Update its status as compatibility patches are implemented and verified.

## Scope and method

The static inventory below scans 13 Forge 1.20.1 jars, plus Jar-in-Jar classes embedded in those jars (including `thermal_core` inside Thermal Foundation); NeoForge 1.21.1 jars were excluded. Runtime validation was initially limited to Gendustry and its required dependencies. The user has now confirmed that Gendustry appears to work in-game with the current compatibility adjustments; the next runtime target can be selected. Additional Forge 1.20.1 mods can be added to `run/mods` as the project expands.

The scan records bytecode method invocations, field accesses, and method/field handles whose symbolic owner begins with `net.minecraftforge`. It compares each owner and member against the current `ForgeOwnerMappings` table. It does not yet cover Forge-added methods invoked with Minecraft owners, descriptor-only references, reflection/string-based lookups, mixin targets, or resource/config references; those require follow-up passes before this can be considered an exhaustive migration audit.

Status meanings:

- `PATCHED`: the current owner/member remap table has a supported mapping. This confirms a transformer mapping exists, not that the corresponding behavior has been exercised in-game.
- `KNOWN_GAP`: the owner is mapped, but this member is not in its supported-member set. Existing transformation may leave the owner unmapped or replace the call with a runtime failure.
- `UNMAPPED`: no owner mapping was found. Verify whether the API still exists unchanged on NeoForge; add a compatibility patch when it does not.

The TSV contains **1,173 unique signatures** across the scanned jars: **1,146 patched**, **21 known gaps**, and **6 unmapped**. Their 9,443 bytecode references are distributed as 9,375 patched, 22 known-gap, and 46 unmapped references (99.3% patched). These are static bytecode-reference counts, not a claim that every reference executes at runtime.

### Why 21 signatures are still known gaps

`KNOWN_GAP` does not mean that all 21 APIs are impossible to support. It means the owner class is recognized but that member has no verified behavior-preserving adapter yet. Some are likely approachable with a focused shim; others expose event state, data formats, or lifecycle behavior that cannot be inferred from a name-only remap. The outstanding entries divide into these areas:

| Area | Signatures | What remains unsupported |
|---|---:|---|
| GUI and rendering | 6 | Four `RenderGuiOverlayEvent` constructors/accessors still expose Forge's window, partial-tick, and named-overlay model; and `ForgeGui.setupOverlayRenderState` / `shouldDrawSurvivalElements` rely on Forge GUI state that is not a direct NeoForge layer API. `RenderLivingEvent.setCanceled` is translated through the target event's cancellable interface and fails explicitly for non-cancellable post events. |
| Crafting JSON helpers | 0 | Both `CraftingHelper.getItemStack` overloads preserve their NBT and air-rejection flags, and `getNBT` parses the legacy JSON/SNBT forms. `getIngredient` uses the target ingredient codec and preserves the legacy `allowEmpty` behavior. |
| Shearing | 2 | `IForgeShearable.isShearable` and `onSheared` are removed extension hooks. A bridge must preserve block-specific eligibility and drops rather than assuming every shearable block follows vanilla behavior. |
| Gameplay and event results | 12 | These cover damage cancellation; spawn-tag access; shield durability; player-interaction cancellation and results; projectile impact results; break-event XP; and `ForgeHooks.onBlockBreakEvent`. Forge damage cancellation now suppresses final health damage through the NeoForge pre-damage hook, but cannot short-circuit the target event dispatch; the other adapters still need to preserve each caller-visible mutable value and control-flow effect. |
| Generic event registration | 0 | The seven Mantle/TConstruct/Thermal Dynamics calls infer the concrete event type from their listener lambda and register a filtered NeoForge listener. Calls whose event type cannot be inferred fail explicitly instead of silently registering with different semantics. |
| Registry helpers | 0 | `DeferredRegister.createOptional` creates an unbound deferred holder for an optional registry; when the registry is absent, presence checks remain false and access still fails as it does on Forge. |
| Baked-model pipeline | 1 | The legacy `QuadBakingVertexConsumer(Consumer)` constructor targets a vertex callback pipeline that changed; an adapter must preserve the emitted quad data, not just accept the callback. |

These are the remaining members in the current scan, not a claim that every one is a permanent blocker. Several are implementation work; the entries above specifically need tests against the supplied mods before they can be called patched. A mapping that only prevents `NoSuchMethodError` is not sufficient if it drops cancellation, registry context, data, ordering, or lifecycle effects.

## Remaining unmapped work

The current TSV contains **6 unmapped signatures** (46 bytecode references), not 12. Five are `ConditionalRecipe` builder methods (45 references); one is `ForgeRegistry.unfreeze()` (1 reference). The strict-NBT constructor and serializer singleton are now bridged to a custom ingredient that stores legacy NBT in `minecraft:custom_data`, tests exact item-and-component equality, and uses registry-aware item-stack streaming. The single-variant conditional advancement builder used by TConstruct is supported; the multiple-variant `ConditionalRecipe` builder is not. TConstruct builds multiple condition-specific recipes under one ID and relies on Forge selecting the first passing variant. NeoForge 1.21.1 `RecipeOutput.withConditions` only adds conditions to an individual output and has no equivalent first-match recipe wrapper; moreover, the legacy builder accepts `Consumer<FinishedRecipe>`, while `FinishedRecipe` no longer exists in the target API. Keep those signatures unmapped rather than emitting duplicate recipe IDs or pretending the old consumer can be adapted.

The projectile impact result is now adapted at the TConstruct call site: its used `SKIP_ENTITY` value becomes cancellation of NeoForge's `ProjectileImpactEvent`, whose dispatch helper returns before normal hit handling when canceled. This preserves TConstruct's pierced-entity handling while allowing the projectile to continue. The remaining registry-mutability signature is `ForgeRegistry.unfreeze()` (1 reference). It changes registry mutability, and NeoForge does not expose an equivalent lifecycle operation, so do not replace it with a no-op.

The 15 entity-spawn references are now handled by `LegacyEntitySpawnPacketStep`: it rewrites the legacy entity-only packet override into NeoForge's tracking-aware `getAddEntityPacket(ServerEntity)` override and constructs the target add-entity packet with tracker state. NeoForge's `ServerEntity` pairing flow sends `IEntityWithComplexSpawn` data separately, so the existing Forge additional-spawn-data interface bridge remains effective instead of being discarded by an entity-only alias.

The tier-drop predicate now uses the 1.21.1 tier's incorrect-block tag. `TierSortingRegistry.byName`, `getName`, and `getSortedTiers` resolve and order the six vanilla tiers through a compatibility adapter; modded tiers not registered in that adapter remain unresolved. The `FluidStack` packet methods use NeoForge's registry-aware stream codec, and the item `FluidUtil.getFluidHandler` lookup wraps NeoForge's `Optional` in the compatibility `LazyOptional`. The mapped GUI overlay tokens preserve identity for the three referenced vanilla layers; unsupported overlay event constructors, windows, and partial-tick access remain known gaps.

`ForgeHooks.onBlockBreakEvent` is a known gap rather than a safe alias: NeoForge's `BlockEvent.BreakEvent` preserves cancellation but has no Forge-compatible experience-to-drop result.

Three compatibility adapters still lose behavior and should not be mistaken for complete translations: TConstruct's `FinalizeSpawn.getSpawnTag()` call is replaced with `null` because NeoForge's `FinalizeSpawnEvent` has no spawn-tag equivalent; `LegacyBlockBreakEvent` returns zero experience and ignores writes because the target break event has no XP field; and empty-click interaction cancellation-result accessors return `PASS` / ignore writes because NeoForge's empty-click hook only exposes cancellation. The TConstruct spawn-tag and empty-click gaps have not been proven harmless in-game.
